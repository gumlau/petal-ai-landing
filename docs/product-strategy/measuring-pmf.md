# Petal GTD 产品市场契合度（PMF）测量指南

## 概述

产品市场契合度（Product-Market Fit，PMF）是创业成功的核心里程碑。对于 Petal GTD 来说，验证 PMF 意味着回答一个根本问题：**我们是否创造了用户真正离不开的产品？**

本文档提供一套系统化的 PMF 测量框架，包括 Sean Ellis 调研问卷设计、留存数据分析方法、PMF 里程碑定义，以及何时开始规模化增长的决策指南。

## 核心原则

基于 `.claude/skills/measuring-product-market-fit/SKILL.md` 的核心原则：

### 1. 使用 Sean Ellis "失望度"调研
> "如果你不能再使用这个产品，你会有多失望？非常失望、有些失望、还是不失望。如果 40% 的用户说'非常失望'，你就走在正确的道路上。" —— Sean Ellis

这是 PMF 的领先指标，可以在长期留存数据可用之前就获得信号。关注"非常失望"群体是判断核心价值的关键。

### 2. 留存是终极指标
> "产品市场契合有一个指标：留存。如果你创造了价值，他们会回来。如果他们不回来，你就没有创造价值。" —— Uri Levine

寻找随时间趋于平稳而非持续下降的留存曲线。"微笑曲线"——用户参与度随时间增加——是最强的 PMF 信号。

### 3. 有 PMF 时你会确定无疑地知道
> "产品市场契合是那种你绝对知道的事情。因此如果你不是绝对知道，你就没有达到。" —— Matt MacInnis

如果存在疑问，你很可能还没有达到 PMF。寻找市场主动把产品"抢走"的感觉。

### 4. PMF 不是静态的——它可能丧失
> "一旦你建立了规模，保护你所建立的东西变得越来越重要。如果你不持续改进产品，一年或五年后你可能会失去产品市场契合。" —— Casey Winters

市场在变化，竞争对手在进步，用户期望在提高。PMF 需要持续维护。

### 5. 参考用户验证 PMF
> "圣杯真的是参考客户——那些足够喜欢产品愿意主动推荐的人。对于 B2B 我希望看到 6-8 个参考客户，对于 B2C 则是 15-25 个，作为 PMF 的指标。" —— Christian Idiodi

在公开发布之前，先从早期用户中获得目标数量的参考客户。

### 6. PMF 存在于特定细分市场，而非普遍存在
> "我们思考的方式是：'我们在特定细分市场中有契合度吗？'以及这个契合度有多强。" —— Karri Saarinen

先在一个细分市场（如早期创业者）找到 PMF，再考虑扩展。在看到自然拉动的地方加倍投入。

### 7. PMF 需要分发渠道，不仅仅是留存
> "如果你有一个留存很好的产品但找不到更多用户，我不认为那是产品市场契合。" —— Casey Winters

真正的 PMF 需要既有留存能力的产品，又有可规模化的内建分发机制。

### 8. PMF 是多阶段的，不是二元的
> "本质上有四个层级：萌芽期、发展期、强劲期、极端期。" —— Todd Jackson

- Level 1（3-5 客户）：关注满意度
- Level 2（5-25 客户）：关注需求验证
- Level 3（25-100 客户）：关注效率
- Level 4（100+ 客户）：可以规模化

### 9. 寻找客户"拉动"
> "我们感觉到问题变了——'你们怎么定价？我们什么时候可以开始 POV？'这才是真正的意向。" —— Raaz Herzberg

真正的拉动表现为客户推动下一步行动，而不是仅仅说"这很有趣"。

### 10. 宕机时无人愤怒 = 没有 PMF
> "在那 20 分钟里我们的客户并不愤怒。这就是我们没有产品市场契合的信号。" —— Jeff Weinstein

如果你的产品宕机而没人注意或抱怨，你还没有解决一个关键性问题。

## 现状分析

### Petal GTD 当前的 PMF 信号评估

基于项目现状，诚实评估当前 PMF 状态：

**当前阶段**：Pre-PMF / Level 0-1

| 信号维度 | 当前状态 | 目标状态 | 差距 |
|----------|----------|----------|------|
| 活跃用户数 | 待统计 | Level 1: 3-5 核心用户 | 未知 |
| Sean Ellis 调研 | 未执行 | >40% "非常失望" | 未知 |
| 7 日留存 | 待统计 | >40% | 未知 |
| 30 日留存 | 待统计 | >20% | 未知 |
| 参考用户 | 0 | 15-25（B2C 标准）| 15-25 |
| 有机推荐 | 无 | 有可追踪的推荐来源 | 完全缺失 |

### 独立开发者场景的 PMF 挑战

作为独立开发者，测量 PMF 面临特殊挑战：

1. **样本量有限**：用户少时统计数据波动大
2. **数据基础设施不足**：可能没有完整的分析系统
3. **反馈渠道有限**：难以触达足够多的用户进行调研
4. **时间和精力限制**：产品开发与用户研究难以兼顾

**应对策略**：
- 重质不重量：深度访谈 5 个用户 > 100 个问卷回复
- 使用免费工具：Tally、Typeform 免费版、Google Forms
- 自己成为第一个参考用户（dogfooding）
- 参考 `docs/product-strategy/startup-ideation.md` 的小样本验证方法

## 关键洞察

### 洞察 1：40% 规则是方向指标，不是绝对标准

Sean Ellis 的 40% "非常失望"规则被广泛引用，但需要理解其适用场景：

- **适用场景**：有一定用户基数（至少 40-50 人）的定量验证
- **不适用场景**：极早期（<10 用户）阶段
- **替代方法**：早期可用定性访谈判断"离不开"程度

**Petal GTD 的务实做法**：
- 0-10 用户：关注定性信号（用户主动反馈、推荐行为）
- 10-50 用户：开始 Sean Ellis 调研
- 50+ 用户：可以依赖定量数据

### 洞察 2：留存曲线形态比数值更重要

> 参考 `docs/product-strategy/north-star-metrics.md` 中的留存讨论

留存曲线的形态揭示 PMF 状态：

```
留存率
100% ┤
     │╲
     │ ╲__________   ← 理想：平稳（有 PMF）
     │  ╲
     │   ╲____       ← 可接受：逐渐平稳（接近 PMF）
     │    ╲
     │     ╲         ← 危险：持续下降（无 PMF）
     │      ╲___
  0% ┼─────────────→ 时间
        7d   30d  90d
```

**GTD 工具的特殊性**：
- 习惯养成型产品，留存曲线需要更长时间观察
- 关键拐点：7 日（习惯形成）、28 日（月度周期）
- 参考 `docs/product-strategy/behavioral-design.md` 中的 7 日留存门槛理论

### 洞察 3：PMF 细分市场优先于普遍 PMF

对于 Petal GTD，可能的 PMF 细分市场：

| 细分市场 | PMF 可能性 | 验证难度 | 市场规模 |
|----------|------------|----------|----------|
| Things 3 Windows 用户 | 中 | 低（明确需求）| 小 |
| 焦虑型知识工作者 | 高 | 中（需深度访谈）| 中 |
| AI 早期采用者 | 高 | 中（需求新兴）| 增长中 |
| 极简主义追求者 | 中-高 | 中 | 小 |
| 独立开发者/创业者 | 高 | 低（容易触达）| 小但高价值 |

**推荐策略**：先在"独立开发者/创业者"细分市场验证 PMF
- 原因：容易触达、需求清晰、高价值用户、符合产品愿景
- 参考 `docs/product-strategy/competitive-analysis.md` 的垂直市场策略

### 洞察 4：拉动 vs 推动是最诚实的 PMF 信号

区分真实 PMF 信号与虚假信号：

**真实 PMF 信号（拉动）**：
- 用户主动问"什么时候上线？"
- 用户主动推荐给朋友
- 用户主动询问付费计划
- 用户报告 bug 并期待修复
- 产品下线时用户抱怨

**虚假 PMF 信号（推动）**：
- 用户礼貌地说"挺有意思"
- Product Hunt 发布时的短暂热度
- 朋友/家人的支持性反馈
- 用户试用但从不回来
- 大量注册但极低活跃

### 洞察 5：Pivot 信号与 PMF 测量相辅相成

> 参考 `docs/product-strategy/startup-pivoting.md` 的 Pivot 信号监控

PMF 测量结果直接指导 Pivot 决策：

| PMF 测量结果 | 行动建议 |
|--------------|----------|
| Sean Ellis <20% | 强 Pivot 信号，需重新审视问题定义 |
| Sean Ellis 20-30% | 弱 Pivot 信号，尝试产品调整 |
| Sean Ellis 30-40% | 接近 PMF，专注优化 |
| Sean Ellis >40% | 可能有 PMF，开始验证增长 |
| 7d 留存 <10% | 激活问题或价值问题 |
| 7d 留存 10-20% | 需要优化首周体验 |
| 7d 留存 >40% | 良好信号 |

## 行动建议

### 设计 Sean Ellis 调研问卷

**问卷设计**（适用于 Petal GTD）：

```markdown
# Petal GTD 用户调研

**核心问题**（必答）：
Q1. 如果明天 Petal GTD 不再可用，你会有多失望？
   - 非常失望
   - 有些失望
   - 不失望

**辅助问题**（帮助理解）：
Q2. 你主要用 Petal GTD 做什么？
   （开放式问答）

Q3. 使用 Petal GTD 给你带来的最大好处是什么？
   （开放式问答）

Q4. 如果 Petal GTD 不可用，你会用什么替代？
   - Things 3
   - Todoist
   - TickTick
   - Apple 提醒事项
   - 纸笔
   - 其他：___

Q5. 你会向谁推荐 Petal GTD？请描述这个人。
   （开放式问答）

Q6. 你觉得 Petal GTD 还需要什么改进？
   （开放式问答）
```

**问卷发放时机**：
- 用户使用 14+ 天后
- 完成至少 10 个任务后
- 避免在功能发布后立即发送

**数据解读**：
- 目标：>40% 选择"非常失望"
- 样本量：至少 40 人才有统计意义
- 关注"非常失望"群体的 Q5 回答——他们描述的就是你的目标用户

### 定义 PMF 里程碑

**Petal GTD 的 PMF 里程碑阶梯**：

```
Level 4: 规模化就绪 ━━━━━━━━━━━━━━━━━━━━━━━━━
│ 指标：100+ 活跃用户，>40% 非常失望，可持续获客渠道
│ 行动：开始增长投入，优化漏斗
│
Level 3: 强 PMF ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
│ 指标：25-100 活跃用户，>35% 非常失望，有机推荐出现
│ 行动：优化留存，测试付费转化
│
Level 2: 发展期 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
│ 指标：5-25 活跃用户，>30% 非常失望，7d 留存 >30%
│ 行动：深挖"非常失望"用户，理解核心价值
│
Level 1: 萌芽期 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
│ 指标：3-5 核心用户，有定性"离不开"信号
│ 行动：每周深度访谈，快速迭代
│
Level 0: Pre-PMF ━━━━━━━━━━━━━━━━━━━━━━━━━━━
  当前阶段：产品开发，寻找早期用户
  行动：发布 beta，dogfooding，寻找第一批用户
```

### 建立留存数据追踪

**基础追踪需求**：

1. **用户活跃定义**
   ```
   活跃 = 当天有以下任一行为：
   - 创建任务
   - 完成任务
   - 查看 Today 视图 > 30 秒
   - 使用 Quick Add
   ```

2. **留存队列（Cohort）分析**
   - 按注册周分组
   - 追踪 D1、D7、D14、D28、D60 留存
   - 可用 Mixpanel/Amplitude 免费版，或自建简单追踪

3. **关键指标仪表板**
   ```
   每周监控：
   - 新用户数
   - 7 日留存率
   - 周活跃用户数（WAU）
   - 任务完成数（北极星指标）
   - Sean Ellis 调研结果（累计）
   ```

### 何时开始规模化增长

**规模化增长的前提条件清单**：

| 检查项 | 目标值 | 当前状态 |
|--------|--------|----------|
| Sean Ellis >40% | >40% | 待测量 |
| 7 日留存 | >40% | 待测量 |
| 30 日留存 | >20% | 待测量 |
| 参考用户数 | 15+ 愿意推荐的用户 | 0 |
| 有机增长 | 有可观察的口碑推荐 | 无 |
| 单位经济 | CAC < LTV/3 | 未知 |
| 获客渠道 | 至少一个可规模化渠道 | 未验证 |

**规模化增长的决策框架**：

```
Q1: Sean Ellis 是否 >40%？
    ├── 否 → 继续优化产品，不要增长投入
    └── 是 → Q2

Q2: 7 日留存是否 >40%？
    ├── 否 → 优化首周体验，不要增长投入
    └── 是 → Q3

Q3: 是否有 15+ 参考用户？
    ├── 否 → 继续积累早期用户，小规模测试
    └── 是 → Q4

Q4: 是否有可规模化的获客渠道？
    ├── 否 → 测试不同渠道，寻找产品-渠道契合
    └── 是 → 可以开始规模化增长投入
```

**警告：过早规模化的代价**

> "在 PMF 之前的付费增长只是在烧钱，还可能损害你的品牌。" —— 核心原则

过早规模化的问题：
- 获取的用户留不住，浪费获客成本
- 差评可能损害品牌
- 稀释了对产品优化的注意力
- 给自己错误的增长信号

**Petal GTD 的务实建议**：
- 在达到 Level 3（25-100 活跃用户）之前，不要任何付费获客
- 免费渠道：独立开发者社区、Twitter/X、Product Hunt（等 PMF 确认后）
- 把时间花在产品优化和用户访谈上

### 短期行动计划（1-4 周）

**Week 1: 建立基础**
- [ ] 在产品中添加基础事件追踪（注册、登录、创建任务、完成任务）
- [ ] 创建 Sean Ellis 调研问卷（使用 Tally 或 Google Forms）
- [ ] 定义"活跃用户"的具体标准

**Week 2: 寻找早期用户**
- [ ] 发布 beta 版本到独立开发者社区
- [ ] 自己作为第一个深度用户（dogfooding）
- [ ] 邀请 5-10 个潜在用户试用

**Week 3: 收集反馈**
- [ ] 对每个试用用户进行 15-30 分钟访谈
- [ ] 记录定性 PMF 信号（参考"拉动 vs 推动"）
- [ ] 开始发放 Sean Ellis 调研

**Week 4: 分析与迭代**
- [ ] 分析调研结果
- [ ] 识别"非常失望"用户的共同特征
- [ ] 根据反馈优先级排序产品改进

### 中期行动计划（1-3 月）

**Month 1: 验证细分市场**
- 确定主要细分市场（建议：独立开发者/创业者）
- 在该细分市场中达到 10+ 活跃用户
- 持续 Sean Ellis 调研

**Month 2: 优化核心体验**
- 根据"非常失望"用户反馈优化产品
- 目标：7 日留存 >30%
- 开始积累参考用户

**Month 3: PMF 确认**
- 目标：达到 Level 2（5-25 活跃用户，>30% 非常失望）
- 如果达不到，参考 `docs/product-strategy/startup-pivoting.md` 评估是否需要 Pivot
- 如果达到，开始测试付费转化

## 思考问题

在测量和追求 PMF 的过程中，持续思考这些问题：

1. **"非常失望"的用户失望的真正原因是什么？** 是功能？体验？还是产品代表的理念？

2. **如果 Things 3 明天推出跨平台版本，Petal GTD 的用户会流失多少？** 这揭示了真正的差异化程度。

3. **用户在没有 Petal GTD 之前是如何解决问题的？** 了解替代方案帮助理解真正的竞争格局。

4. **产品的"意外用途"是什么？** 用户如何以你没想到的方式使用产品，这可能揭示隐藏的 PMF 方向。

5. **如果只能保留一个功能，用户会选哪个？** 这揭示了核心价值。

6. **我们解决的是"维生素"问题还是"止痛药"问题？** 止痛药问题更容易达到 PMF。
